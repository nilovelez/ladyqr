# LadyQR roadmap

LadyQR is a privacy-oriented QR code generator and URL shortener, built to run on a minimal shared hosting plan (Apache with `.htaccess`, PHP and SSL, about 100 MB) and to be easy for anyone to set up.

## Principles

- Minimal dependencies: ideally none at runtime. No build step.
- Stage 1, the QR code generator, runs entirely in the browser. Nothing is sent to the server, and a strict CSP guarantees it.
- Stage 2, the URL shortener, is private and single-user. It is a small PHP admin that writes a delimited block of redirects into `.htaccess`, so redirects are served by Apache without running PHP. When no redirect matches, the QR code generator loads.
- Anyone must be able to deploy the same thing: one configuration file, our own authentication and bundled documentation.
- License: GPL-2.0-or-later (see `LICENSE`).

## Design decisions

- **Outputs:** PNG and SVG.
- **Configuration file:** a PHP file that returns an array. It is looked up in the web root first and, if missing, one level above, like `wp-config.php`. The file is called `ladyqr-config.php`; a `.gitignore` entry keeps the real one out of the repository and `ladyqr-config.sample.php` documents it.
- **Authentication:** a single user, written in-house: `password_hash`, native PHP sessions, CSRF tokens, login rate limiting, and `HttpOnly`, `Secure` and `SameSite` cookies.
- **No default password:** until one is configured, `/admin/` does not let anyone in and shows instructions. The only way to enable it is editing the configuration file, never through the web. A browser-based page generates the password hash.
- **`.htaccess` writes:** only inside a `# BEGIN` / `# END` block, validated, atomic (temporary file plus rename), locked and with a `.bak` copy. A syntax error must never take the site down.
- **Distribution:** clonable repository first, and later a release `.zip` ready for FTP.
- **PHP is required anyway:** the project needs PHP regardless (the shortener), so the editor page is generated by PHP and what reaches the user is static HTML.
- **Multilingual:** the interface is translatable the WordPress way, so standard tools (`wp i18n make-pot`, Poedit, Loco, GlotPress) work on it.
  - All text is written in English in the code with gettext-style functions, `__( 'Download', 'ladyqr' )` and `_e()`, using the `ladyqr` text domain. A string with no translation stays in English.
  - Translations live in `languages/`: `ladyqr.pot`, and `.po` and `.mo` files named like `ladyqr-es_ES.po`. The compiled `.mo` is committed, because the hosting has no tools.
  - A small in-house `.mo` reader loads the file. It does not use PHP's `gettext` extension, which is not reliable on shared hosting. With the default language, English, no file is read.
  - The language is a single site-wide setting in the configuration file (`'language' => 'es_ES'`), English by default; visitors do not choose it.
  - No gettext plurals. A small `__plural( __( 'singular', 'ladyqr' ), __( 'plural', 'ladyqr' ), $number )` helper picks the singular for exactly 1 and the plural otherwise, and the caller applies `sprintf`. Translation tools see only the inner `__()` calls, so each form is its own string, with a `translators:` comment to say they go together. It supports two forms only, which is enough for English and Spanish; languages with more forms would need real gettext plurals.
  - Strings needed by the browser-side JS are translated in PHP and written into the page as a `<script type="application/json">` block, which a strict CSP does not block, and read with `JSON.parse`.
  - Lands in M0, because the page is generated by PHP from the start.
- **Not now:** migrating the old short links previously used on the author's own `1qr.es` domain.

## Milestones

Work is done one milestone at a time, each in its own branch, and a milestone is only started when explicitly authorized.

### M0. First publishable QR code generator (proof of concept)

The base of the project, not a throwaway: it lives at the repository root and is the first thing published on the author's `1qr.es`.

- A page generated by PHP (`index.php`) that delivers static HTML, CSS and JS: no dependencies, no build step.
- In-house QR encoder (`assets/js/qr.js`): byte mode (text and URLs), versions 1 to 40, the four error correction levels, automatic version and mask.
- Rendering helpers (`assets/js/render.js`): SVG and PNG output, and conversion of the module matrix to and from an array of `'0'/'1'` strings.
- The editor from the approved mockup: collapsible settings as the card header (error correction, margin, colors), one text field, the QR code, and a download button for PNG 500 px with PNG 1000 px and SVG in its menu. Help dialog and footer included.
- The settings are remembered in the browser's `localStorage`, never the text, and nothing is sent anywhere.
- A small warning under the QR code when the module and background colors have a contrast ratio of 4:1 or less.
- Translations as described above, with English and Spanish (s_ES).
- No external requests, enforced by a CSP sent by PHP.
- Done when a list of inputs (short and long URLs, accents, emoji) produces codes a real reader decodes, and it is published on `1qr.es`.
- At the end, decide whether writing the encoder ourselves was worth it or a minimal library should be vendored instead.

### M1. Hosting spike

Verify what the target hosting allows before building the shortener: `Redirect` and `ErrorDocument 404` in `.htaccess`, PHP rewriting a block of `.htaccess`, `Header` for the CSP, available PHP version and HTTPS. Part of this comes for free from deploying M0. If something fails, redesign the shortener before writing it.

### M2. Consolidate the encoder

Automated tests (Node's built-in runner, development only), all data modes and configurable error correction levels.

### M3. Complete editor

Colors, size, margin, and PNG and SVG downloads.

### M4. Configuration and authentication

Configuration file lookup, the no-password notice, single-user login, and the browser-based hash generator.

### M5. Redirect manager

Create, edit and delete short links, safe `.htaccess` block writes, and the fallback to the QR code generator.

### M6. Documentation and packaging

Installation README, troubleshooting, `config.sample.php` and a release `.zip`.
